# Changelog

## Unreleased

### Added

- Image input in the web composer. A `图片` button next to the send button opens a file picker (`image/*`), each chosen file becomes a removable chip above the input, and the message goes out with the image attached as a base64 `image_url` part the model reads beside the text — for the workspace chat and for a rob's turn alike. The same rules the CLI enforces are applied before the send: `png`, `jpg`, `jpeg`, and `webp` only, 8 MiB per file, 8 files per message, with a Chinese message on the input naming the file and the reason. `POST /api/send` takes an optional `images` list and validates it server-side, answering `400` with the reason for a malformed list, a disallowed media type, a payload over the cap, or too many images; the client surfaces that message rather than sending silently. A queued interjection keeps its own images.

- Web bot panels. A rob is now first-class in the browser. The server adds `GET /api/bots/:bot/transcript` (the bot's current session replayed from the ledger, plus its session summaries), `GET /api/bots/:bot/memory`, `POST /api/bots/:bot/memory/forget` (`{id}`), and `POST /api/bots/:bot/wake` (`{everyMs, prompt}` to set, `{clear: true}` to clear), each answering `501` when the hub cannot serve it, `404` for an unknown bot, and `400` for a bad body. Selecting a rob in the client loads its transcript and memory on demand and gives it three tabs — **对话**, **记忆**, and **唤醒**. The sidebar shows the bot's own session list (create, reopen, close) beside the workspace chat's; the transcript reloads from the ledger on selection; the 记忆 tab lists each entry with a `删除` button that forgets it by id; and the 唤醒 tab reads the bot's schedule and writes it back to `<workspace>/my-agent.json`, re-arming the live timer. When a non-loopback server refuses a request for lack of the token, the client shows an auth banner naming the `?token=` fix. `scripts/bot-e2e.ts` drives the four new surfaces on the real artifact, and a proactive wake whose approval is never answered is denied after a timeout so it cannot hang a turn forever.

- Full bot and session management in the web. A bot can now be edited and deleted, not only created: `PATCH /api/bots/:bot` replaces its role, model, and backend (keeping its ledger, memory, and wake) and `DELETE /api/bots/:bot` removes its `my-agent.json` entry, stops and drops its runtime, denies its pending approval, and deletes its ledger file, behind a `设置` tab whose confirm says the memory goes too. Sub-agent activity is visible: the serve layer no longer drops a rob's `subagent` event, the wire carries each `{parent, id, at, event}`, and a `子 Agent` tab renders it with the same mapping the TUI's `SubagentView` uses, capped per bot. A session can be renamed and deleted (`POST /api/sessions/delete|rename {bot, id[, title]}`) for the workspace chat and for a bot alike — a chat session file gains an optional `title`, a bot's turns gain a `sessionTitles` map on the ledger record, neither bumps its schema version, a rename leaves `updatedAt` alone so the list order is stable, and deleting the live session moves to the newest remaining one or starts a fresh session. One `GET /api/search?q=` scans the workspace's chat sessions and every bot's turns for the current workspace, case-insensitively and read-only, returning grouped sessions with bounded snippets; a sidebar search box opens a hit the same way the lists do. The chat list gains rename and delete too, through one `SessionRow` shared with the bot list.
- Durable bots. A rob is now a persistent teammate whose long-term memory and turn log live in one atomic JSON ledger at `<data root>/bots/<name>.json` (`MY_AGENT_BOTS_DIR` overrides the root, default `~/.local/share/my-agent`). The ledger is keyed by name alone, so one bot name is one subject across every workspace, while each turn records its `workspaceRoot` so a transcript is never replayed into another project. A bot session is a temporary in-memory channel over that ledger: opening one drops the live transcript without touching memory, reopening a past session replays it from the ledger's turns, and the session list is a read-side projection of those turns, so both survive a restart. A `wake` block in a rob's `my-agent.json` entry (`{ "everyMs": 3000, "prompt": "..." }`, minimum 1000 ms) wakes it on a wall-clock interval with no message, committing a turn attributed `wake: "interval"`; the schedule is configuration that re-arms from the file on every start and is never persisted. `my-agent serve --workspace <root>` selects the initial workspace, and `POST /api/workspaces` swaps the active workspace to a fresh disposable scope at runtime, refusing while any bot or the chat is mid-turn; recent roots are recorded in `workspaces.json`. The workspace chat is now an ordinary session list beside the bot roster rather than a bot: `assistant` is reserved for it, creating a bot never replaces it, and the previous workspace-as-a-bot framing (and `BotInfo.kind`, `newChat`, `openChat`) is retired.
- Windows bash sandbox (unverified). On `win32`, `bash` detection now looks for `pwsh` then `powershell.exe` and, when one is on `PATH`, runs the command through a shipped PowerShell helper that is intended to create a Windows Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, a 64-process cap, and a bounded timeout, so the whole process tree is torn down when the helper exits. The helper has not run on a real Windows host; its process cap and kill behavior are unverified. The Windows backend is intended to manage only process lifecycle, not filesystem or network isolation, so `sandbox.mode = "require"` refuses on Windows and `auto` warns. Linux detection and planning are unchanged.
- Plugin system. A top-level `plugins` array of module specifiers in `my-agent.json` or the global config loads in-process ESM modules that contribute tools, slash commands, and extra system-prompt text. A spec starting with `.` or `/` resolves against the workspace root; anything else is a bare package name resolved from `node_modules`, and project and global specs merge and dedupe. Plugin tools join the agent's tool list alongside MCP tools, plugin commands merge into the TUI slash-command menu, and plugin system prompts are appended to the agent's extra instructions. A plugin that fails to import, is missing a `name`, or has a tool without an `execute` is reported and skipped without stopping the others, and a tool name that collides with a built-in tool or another plugin's tool rejects that plugin with a message naming both. Plugins run in-process with full privileges (outside the bash sandbox), so only load trusted code; TypeScript plugins are out of scope (ESM only).
- Image input. `my-agent run --image <path> "..."` (repeatable, and on the root command too) attaches an image as an OpenAI-style `image_url` content part with a base64 data URL, alongside the text, so vision-capable models can read a screenshot or diagram. Supports `.png`, `.jpg`, `.jpeg`, `.gif`, and `.webp`, and rejects a missing file, an unsupported extension, or a file over 8 MiB before the run starts. The TUI `/image <path>` command attaches a pending image (shown in the status row) that the next submitted message carries and then clears, and `/clear` or a new session drops it. Images round-trip through saved sessions.
- LSP diagnostics. A top-level `lsp.servers` map in `my-agent.json` or the global config starts a language server lazily per file extension and exposes a read-only `diagnostics` tool that returns its diagnostics as `<path>:<line>:<col> <severity> <message>` lines, or a `no diagnostics` line when clean. Each server takes `command`, `extensions`, and optional `env`, `initialization`, and `disabled`. The server starts on first use, is reused, runs as your user without sandboxing, and shuts down cleanly on dispose. An unknown extension returns an error naming the configured extensions, and the tool defaults to `allow`.
- `web_fetch` tool. The agent can retrieve an `http` or `https` URL during a turn. `markdown` and `text` return readable text with HTML tags stripped, and `html` returns the raw body. A non-2xx status, a bad URL, a network error, a timeout, or an abort returns an error. The tool asks for permission by default.
- `web_search` tool. The agent can query a configured search provider (brave, tavily, or searxng) and get a numbered list of titled result snippets. It reads a top-level `search` block (`provider`, `apiKeyEnv`, `baseURL`) from `my-agent.json` or the global config, defaults to brave, and returns an error naming the missing setting when the provider is unconfigured. The tool asks for permission by default.
- `semantic_search` tool. A top-level `embeddings` block (`baseURL`, `model`, `apiKeyEnv`, optional `dimensions`) in `my-agent.json` or the global config registers a read-only semantic search over a local vector index. Files are chunked 40 lines with 10 lines of overlap and embedded through the configured OpenAI-compatible endpoint in batches of 64, and unchanged files are reused by mtime and size. The index is written atomically to `~/.local/share/my-agent/index/<project>/index.json` (overridable with `MY_AGENT_INDEX_DIR`), and a model or dimensions change rebuilds it. A search returns the top `k` chunks as `<path>:<startLine>-<endLine> (score 0.xx)` with the chunk text. The tool defaults to `ask`, and a missing key names the `apiKeyEnv` variable.
- Dollar cost tracking and a run budget. The headless `[usage]` line and the TUI status row now report the accumulated cost in USD, computed from per-model input, output, and cache-read rates (`deepseek-flash` and `deepseek-v4-pro` have prices; unknown models cost 0). `--max-cost <usd>` on the root command and the `run` subcommand stops a run with a `budget` done reason once the cost exceeds the cap, and exits non-zero. No cap by default.
- `task` tool for the solo agent. It delegates one self-contained sub-task to a fresh sub-agent and returns only its final text, capped at 4000 characters. The sub-agent inherits the parent's provider, model, workspace, permissions, and thinking, and receives the standard tools without `task`, so it cannot recurse (hard depth cap of 1). A rejected sub-agent run becomes a tool error instead of throwing. Available in headless runs, the TUI, and the web UI, and it defaults to `ask`.
- `my-agent sessions fork <id>` copies a saved session into a new one with a fresh id, carrying over its messages and model, and prints the new id. `--at <n>` truncates the fork to the first `n` messages. An unknown id prints a clear error and exits non-zero.
- Token auth for non-loopback web binds. `my-agent serve` on a host other than `127.0.0.1`, `::1`, or `localhost` generates a random token at startup, requires it on every `/api/*` request (a `?token=` query parameter or an `Authorization: Bearer` header), answers a missing or wrong token with `401`, and prints the startup URL with the token appended. Loopback binds are unchanged and need no token.
- Local web UI. `my-agent serve` starts a loopback HTTP server and a browser client that streams answers, renders Markdown and tool cards, folds reasoning, and shows the same permission dialog and allow-all switch as the TUI. `Stop` cancels the running turn with `Rob.abortTurn`/`Team.interrupt` and keeps the session alive, a message sent mid-turn is queued and injected at the next step, and the default assistant is a persistent session chat. The rob area is separate: create a rob from the sidebar or the Bot 广场, it is appended to `my-agent.json` and starts running, and the panel shows per-rob status, DMs, and notices. `assistant` is reserved for the workspace chat.
- Keyless web start and an in-app Settings dialog. `my-agent serve` starts and serves the UI with no API key configured anywhere, and the Settings dialog sets the provider preset, model, an optional custom base URL and key environment, and the API key. The key goes to the existing `credentials.json` (`0600`) and the rest to `config.json`, and the provider is rebuilt in place so the next turn uses it with no restart. The key is never sent back to the browser, never written to `config.json`, and never logged, and `POST /api/settings` is refused when the server is bound to a non-loopback host.
- Model Context Protocol (MCP) servers over stdio. A top-level `mcp.servers` map in `my-agent.json` or the global config starts each server, exposes its tools as `mcp__<server>__<tool>`, and asks before running one by default. A failing server prints `mcp <server>: <error>` and never stops the others. Servers run as your user and are not sandboxed, and only stdio is supported.
- Native team robs receive the configured MCP tools. One connection set serves the whole team run and is disposed when the team stops. An `mcp__...` call from a rob goes through that rob's authorizer, so it asks by default and shows in the approval dialog with the rob's name. A `cli` rob (`pi` or `opencode`) runs its own tool registry and uses its own MCP configuration instead, and a `delegate` sub-agent does not receive MCP tools.
- Persistent `opencode` CLI backend for robs: a private long-lived `opencode serve` process with one session per rob, mid-turn `steer` interjections, and SIGTERM teardown on stop. Configure with `{ "kind": "cli", "command": "opencode", "provider": "deepseek", "model": "deepseek-v4-flash" }`.
- `claude` CLI backend for robs: one `claude -p` process per turn, with a `--session-id` on the first turn and `--resume` after so the rob remembers its history. Its config is isolated under `~/.config/my-agent/claude/<name>/` via `CLAUDE_CONFIG_DIR` (overridable with `MY_AGENT_CLAUDE_CONFIG_DIR`), `allow` tools are exposed with `--allowedTools`, and `ask`/`deny` tools are denied with `--disallowedTools`. Interactive approval is not bridged, so `ask` tools are denied. Configure with `{ "kind": "cli", "command": "claude" }`.
- OS-level sandboxing for the `bash` tool, configured by a top-level `sandbox` block (`mode`, `network`, `writablePaths`). The backend is chosen in priority order: bubblewrap (`bwrap`), then Landlock through `python3`, then none. `auto` warns and runs unsandboxed when no backend exists, `require` refuses, and `off` disables the sandbox. The sandbox denies TCP by default and limits writes to the workspace, the temp directory, and `writablePaths`. Only the `bash` tool is sandboxed.
- `opencode` robs now expose `ask`-level tools and answer each opencode `permission.asked` request through the rob's authorizer and the shared FIFO approval queue, so the dialog shows the rob's name and `allow once` / `allow always` / `deny` behave like every other rob. A pending request is rejected on turn abort or dispose so opencode never blocks on a stopped server.
- Interactive `my-agent setup` wizard and first-run TUI setup that stores an API key in `~/.config/my-agent/credentials.json`, with environment variables taking precedence.
- Runtime allow-all mode in the TUI: `/allow-all` (or `Ctrl+A`) toggles a run-wide switch that grants every permission request, `/allow-all on` and `/allow-all off` set it explicitly, an `allow-all` marker appears in the status row while it is on, and each dangerous call it approves prints one `allow-all: auto-approved dangerous <tool> <subject>` line to the transcript. Deny rules still win, nothing persists to `my-agent.json`, one switch covers every rob, and `--yes` is unchanged.
- Session persistence. The TUI and headless runs save the transcript after every turn under `~/.local/share/my-agent/sessions/<project>/`, and `--continue` (newest) or `--session <id>` resumes one. `my-agent sessions list` prints them and `/clear` ends the current session to start a new one.
- Context compaction. `/compact` summarizes the older messages into a `[compacted summary]` and keeps the recent ones; automatic compaction runs before a turn when the context estimate exceeds `compaction.thresholdTokens` (default 100000) with `compaction.auto` on. The summary is a persisted `user` message, so a resumed session keeps it, and the TUI shows a `compacted summary (N chars)` line instead of the raw text.
- `@file` mentions. Typing `@` completes workspace files with an anchored accept that replaces only the token, and sending a message expands each resolvable `@path` into a bounded `Referenced files` block so the model does not need a separate read.
- Tool-lifecycle hooks. A top-level `hooks` block in `my-agent.json` runs a shell command before (`preToolUse`) or after (`postToolUse`) each tool call, matched by a tool-name glob (`*` matches all). A pre hook exiting non-zero blocks the tool with its stdout as the reason; a post hook runs after the tool and never changes the result.
- Custom slash commands. Markdown files in `<workspace>/.my-agent/commands/*.md` define a command with YAML frontmatter (`name` in kebab-case, one-line `description`) and a prompt body. Typing `/name args` sends the expanded prompt, substituting `$ARGUMENTS` (or appending the arguments when the body has none), and the suggestion menu lists custom commands after the built-ins. The built-in names are skipped and a missing directory or malformed file is ignored.
- Machine-readable headless output. `my-agent run --output-format json "..."` (and the root `my-agent --output-format json "..."`) writes one JSON object per agent event plus a final `{"type":"summary",...}` object to stdout for scripting and CI, and suppresses the human text and `[tool]`/`[reasoning]`/`[usage]`/`[done]` stderr lines. The default `text` mode is unchanged, and exit codes are the same.
- `my-agent init`. Drafts an `AGENTS.md` for the current workspace from a scan of `package.json`, `README.md`, and the top-level file listing, then one model call whose `text_delta` events are concatenated and written to `<workspace>/AGENTS.md`. It prints the path on success, refuses to overwrite an existing file unless `--force` is passed, and reports the existing missing-key message without calling the model when no API key is configured.
- External-agent management. `my-agent agents` (`list`) prints the agent catalog with its installed state, and `my-agent agents install <id>` resolves the id, prints the exact global npm command, confirms on stdin (skippable with `--yes`), streams the job, and exits non-zero unless the binary re-probes as installed. The web server adds `GET /api/agents`, `POST /api/agents/install` (`{id, confirm}`), and `POST /api/agents/cancel`, all loopback-only for the writes and streamed over `/api/events` as `agents` and `agent_job` events; a new Agents panel and the create-bot dialog's `未安装 · 安装` affordance drive them. Installing is a global `npm install -g` as the user: no `sudo`, no piped script, lifecycle scripts allowed because the CLIs need their bin shims.

### Changed

- Rob `opencode` backends now run isolated under `~/.config/my-agent/opencode/<name>/` and receive the configured provider key as its environment variable, so rob sessions stay out of your own opencode data and a key stored with `my-agent setup` authenticates the child without exporting anything.
- An `opencode` action is exposed as a blanket `allow` only when its rules cannot resolve any subject to something else: a scalar `allow`, or a list of catch-all `allow` entries. A pattern-specific, `deny`, or `ask` entry gates the action as `ask` instead, closing a bypass where `[{ "pattern": "rm *", "action": "deny" }, { "pattern": "*", "action": "allow" }]` was translated to an unconditional allow. `write_file` and `edit_file` share opencode's `edit` action and merge most-restrictively.
- Tool-lifecycle hooks now fire on rob and team turns, not only the solo paths. A native rob applies the project hooks to its own tool calls and to the sub-agents it starts through `delegate`; a `cli` rob runs its own external registry and keeps its own hooks.

### Fixed

- An approval the server will time out now shows it. `ApprovalRequestInfo` carries `expiresAt`, the rob's approval queue reports the deadline of the request it armed (and re-emits a queued request with the deadline it gets when it is promoted to the head), and the dialog ticks a countdown that turns into a warning color inside the last 30 seconds next to the queued count. The workspace chat arms no window and says so with a null deadline instead of a fabricated one.
- Deleting a memory entry asks first and can now fail visibly. The 记忆 panel's `删除` arms a per-row `确认删除？` with a `取消` escape instead of writing on the first click, the panel awaits the request instead of discarding its promise, and a refusal (an id the ledger no longer has, a store failure) prints the server's reason above the list. The other three bot calls — selecting a bot, setting a wake, closing a bot session — no longer swallow a non-401 failure either: a 401 still raises the auth banner and anything else lands on the error banner with the server's message.
- A bot's session list no longer replaces the workspace chat's. A bot reports its sessions with its own `bot_sessions` event carrying the bot name and its current session id, and the client keeps per-bot session maps, so creating or reopening a bot session leaves the chat's `sessions`/`activeSessionId` untouched. A regression guard in `scripts/bot-e2e.ts` opens a bot session and asserts the first session event is `bot_sessions` and that no chat `sessions` event arrives while the interval timer runs.
- Plugin loader and Windows sandbox hardening. Plugin tools now require a string `description` and a boolean `readOnly` (defaulting to `false`), and commands require a `description`, so a malformed plugin is a per-plugin error instead of handing `undefined` to the provider. A plugin command whose name collides with a built-in command, a file-based command, or another plugin's command is rejected with a message naming the collision, a spec listed twice loads once, and bare specifiers resolve from the workspace root with escape and absolute-path handling. One throwing plugin disposer no longer rejects the run's teardown, and plugin system prompts merge with any existing extra instructions instead of replacing them. The Windows helper now sets `JOB_OBJECT_LIMIT_ACTIVE_PROCESS` so the process cap applies, kills the job and exits non-zero when a bounded wait times out, and runs the command from a temp `.cmd` file so quotes and trailing backslashes survive, and executable detection no longer returns a directory.
- Semantic search hardening. A query or chunk vector whose length differs from the index now errors instead of scoring a prefix, and the build rejects an embedder that returns a missing, empty, or wrong-dimension vector rather than persisting a zero-scoring stub. The embeddings call has a 30 s timeout and honors the turn's abort signal, the index is only written when a file was added, removed, or edited (serialized with a per-index file lock), and a workspace over the 5000-file cap reports a truncation warning. Nested `.gitignore` files are honored and a secret denylist (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `*.p12`, `.npmrc`, `credentials.json`, `*.kdbx`) is always excluded before any text is embedded.
- Image input caps. A message is limited to 8 images and 20 MiB of base64 data, enforced in `--image` collection and the shared image reader, so over-cap input is rejected before the provider is called.
- A `cli` rob now receives the resolved provider key in its environment, so `pi` authenticates from a key stored with `my-agent setup` or the web Settings dialog instead of reporting "No API key found".
- A `cli` rob whose command is not on `PATH` is rejected at creation, and an already-saved one reports an actionable "command not found on PATH" message instead of the raw `spawn <cmd> ENOENT`.
- LSP diagnostics. A crashed server now restarts on the next request instead of hanging later calls, concurrent requests for the same file all resolve, repeated requests send `didChange` with a bumped version rather than a second `didOpen`, and `dispose` sends `didClose` for every open file. The client answers `workspace/configuration` with an array of `null` (one per requested item) instead of `-32601`, builds the `file://` uri from the file's real path so symlinked files match the server's published uri, rejects promptly on abort, and rejects a `Content-Length` over 64 MiB instead of buffering it. A new `pnpm lsp:smoke` script runs the real `typescript-language-server` against a temp workspace with a type error.

## 0.1.0 - 2026-10-11

### Added

- Provider layer for OpenAI-compatible APIs, with DeepSeek as the default preset and configurable `baseURL`, thinking, and reasoning effort.
- Six tools: `read_file`, `write_file`, `edit_file`, `bash`, `glob`, and `grep`, with workspace path safety and output truncation.
- Agent loop that streams text and reasoning, runs read-only tools in parallel, retries rate limits and server errors, trims context by size, and honors cancellation.
- Headless run (`my-agent run "..."`) with streaming output and exit codes.
- TUI with streaming messages, tool cards, diffs for file edits, a reasoning fold, an input history, and a status bar.
- Permission rules with interactive approval and persistence to the project file, including dangerous-command detection.
- Config precedence across CLI flags, environment variables, the project file, the global file, and built-in defaults.
- Friendly errors for a missing key, an unknown model, network failures, and rate limits.
- Packaging to `dist/index.js` with a `my-agent` bin entry.

### Known limits

- `bash` is not sandboxed.
- Context is trimmed by size, not summarized.
- The TUI has no sessions.
- Windows and macOS are not verified by hand.
