## 0. 结论速览（TL;DR）

1. **Grok 的视觉内核 = 极简黑白（monochrome）**：近黑背景 + 高对比白字，几乎没有彩色，品牌辨识度极高，视觉噪音极低。这是它与其他大模型产品**最直观的差异**。
2. **Grok 的 UI 有两种"身份"**：① **grok.com 独立网页/App**（完整聊天产品）；② **X/Twitter 内嵌 Grok**（沿用 X 的设计语言，是"信息流里的对话框"）。二者同源但气质不同。
3. **交互核心分叉点是"模式选择器"**（Fast / Think / DeepSearch / Imagine 等）：它同时决定**延迟、成本、是否显示思考过程/来源**，是 Grok UI 最值得研究的一环。
4. **Grok 的差异化亮点**：可折叠的思考过程（"Thought for Ns"）、DeepSearch 的**步骤面板 + 知识图谱式可视化 + 编号引用**、以及把 **X 帖子作为内嵌内容卡片**直接渲染在回答里。
5. **可借鉴**：黑白极简建立品牌、模式 chip 管理预期、工具调用/来源作为一等公民内联渲染、思考过程可折叠。

## 1. 整体视觉风格

### 1.1 配色（Color）
- **主基调：单色 / monochrome**。品牌色本质就是**黑 + 白**，没有固定的"品牌彩色"。
  - 暗色主题背景接近**纯黑 / 近黑**（约 `#0A0A0A`–`#000000` 区间 ⚠️）。
  - 正文为高对比白/近白（约 `#FFFFFF`–`#ECECEC` ⚠️）。
  - 次级文字/边框用不同层级的灰（`#8x`/`#3x` 级别 ⚠️）。
- **强调色极其克制**：主按钮、链接、选中态多以**白底黑字或高亮灰**表达，而非彩色。⚠️ 是否有少量彩色 accent（如状态色、错误色）需实机确认。
- **光/暗主题**：**默认暗色**是 Grok 的招牌观感；亮色主题后续版本提供（设置中切换）⚠️。X 内嵌 Grok 则**跟随 X 的主题**（X 暗色为纯黑，亮色为白）。
- **整体气质**：冷峻、未来感、"黑客/极客"风，与 xAI 的品牌调性一致。

### 1.2 字体（Typography）
- 界面使用**现代无衬线（sans-serif）**，字重对比清晰，标题偏 semibold。⚠️ grok.com 的具体字体族（自研 vs 系统栈）需确认。
- **X 内嵌 Grok 使用 X 的字体 Chirp**（与 X 全站统一）⚠️。
- 代码块使用**等宽字体（monospace）**，带独立背景容器。
- 语言上**多语言友好**（中/日/韩等有专门字体回退）⚠️。

### 1.3 圆角（Corner radius）
- **偏大圆角**的整体倾向：
  - 输入框（Composer）为**大圆角矩形（rounded-2xl 级）**，甚至有"胶囊感"。
  - 按钮/模式 chip 常为**全圆角（pill / rounded-full）**。
  - 卡片、代码块、内嵌帖子卡片为 `rounded-xl` 级别。⚠️ 具体数值需实测。

### 1.4 留白与排版（Spacing）
- **中心内容列较窄、留白充足**：对话正文被限制在约 **48–52rem 的中等列宽**（利于阅读行长）⚠️，两侧留大量空白。
- 消息之间**垂直间距较大**，段落呼吸感强。
- 首页/空状态**大留白 + 居中构图**，突出输入框。

### 1.5 Logo 与图标
- Grok 标志为**极简几何标记**（黑白），无渐变、无拟物。
- 图标风格为**线性/极简**，视觉克重轻，与整体极简调性统一。

## 2. 主要界面布局

### 2.1 总体骨架（grok.com 桌面端）
```
┌───────────────┬────────────────────────────────────────┐
│ 侧栏 Sidebar  │  顶栏：会话标题 / 分享 / 更多           │
│ (可折叠)      ├────────────────────────────────────────┤
│  + New chat   │  对话区（纵向消息流）                   │
│  搜索         │    · 用户消息（右对齐气泡）             │
│  历史分组     │    · 助手回答（全宽、无气泡）           │
│    Today      │       - 思考过程（可折叠）              │
│    Yesterday  │       - 工具/检索步骤                   │
│    Previous   │       - 引用来源 / X 帖子卡片           │
│  底部：账号   │       - 代码块 / 图片 / 报告            │
│   设置/升级   ├────────────────────────────────────────┤
│               │  输入区 Composer（居中，大圆角）        │
│               │   [附件][Imagine] … [模式chip][发送]    │
└───────────────┴────────────────────────────────────────┘
```
⚠️ 各元素的**确切名称/位置随版本变化**，需实机确认。

### 2.2 首页 / 空状态（Home）
- **居中构图**：Logo / 问候语 + 大型输入框居于视觉中心。
- 下方常有**建议 prompt chip / 提示卡片**（引导用户提第一句话）⚠️。
- 输入框获得焦点即有"开始新对话"的暗示。

### 2.3 侧栏（Sidebar）
- **可折叠**左侧栏；顶部「新建对话（New chat）」。
- **会话历史按时间分组**（Today / Yesterday / Previous 7 days…）。
- **搜索**入口（会话检索）。
- 底部：**用户账号、设置、订阅/升级（SuperGrok）入口** ⚠️。
- 历史条目 hover 时有**重命名 / 删除**等操作。

### 2.4 对话区与消息气泡
- **用户消息**：**右对齐**，包在**圆角灰色气泡**中。
- **助手回答**：**全宽、无气泡**，直接铺在背景上（与 ChatGPT/Claude/Gemini 一致的现代范式）。
- 助手消息下方/悬停显示**操作行**：复制、重新生成、继续、点赞/点踩、分享 ⚠️。
- 长回答支持**结构化渲染**：标题、列表、表格、代码块、引用。

### 2.5 输入框（Composer）
- **大圆角、自动增高**的 textarea 容器。
- 左侧/底部**动作簇**：附件（回形针，图片/文件）、**Imagine（图像生成）**、可能的相机/麦克风 ⚠️。
- 右侧：**模式/模型 chip + 圆形发送按钮**；生成中该按钮变为**停止（Stop）**。
- 支持 **Enter 发送 / Shift+Enter 换行**；支持**拖拽文件、粘贴图片**。

### 2.6 模型/模式选择器（差异化重点）
- 位于 Composer 附近的**下拉 chip**。
- 典型选项（⚠️ 名称随版本演进）：**Auto / Fast / Expert（Grok 4 档）/ Grok 3 / Think / DeepSearch / Imagine**。
- 选择不同模式 → 后端走**不同推理/检索管线** → 前端呈现**不同等待形态**（见 §3）。
- 这是 Grok 与 ChatGPT「模型下拉 + 工具开关」模式**最相似的组件**，但 Grok 更**强调"模式"语义**。

## 3. 交互细节

### 3.1 流式输出（Streaming）
- **逐 token 流式渲染**，配**停止（Stop）按钮**与**自动滚动**。
- 用户**手动上滑时自动滚动应暂停**（否则无法阅读历史）——现代 AI 页面通用做法。
- 断流/出错有**重试入口**。

### 3.2 思考过程（Reasoning）
- 用 **"Thought for N seconds"** 形式的**可折叠区块**承载推理过程，默认收起、点击展开。
- 是 Grok「Think」模式最直观的可见产物，也是"预期管理"的关键。

### 3.3 工具调用 / 检索展示
- 工具调用以**内联步骤/卡片**形式出现，例如"正在搜索 X""正在浏览网页"，并**实时更新状态**。
- 是"agent 在干活"的**唯一可见证据**，因此被当作一等公民渲染。
- DeepSearch 会展示**多步骤面板**，最后产出**结构化报告**，并配**知识图谱/思维导图式可视化**（Grok 的辨识度亮点之一）⚠️。

### 3.4 引用来源（Citations）
- 正文中**编号上标引用**，可点击跳转。
- 底部/侧边**来源列表**（网页链接）。
- **X 场景特化**：把 **X 帖子直接渲染成内嵌卡片**（头像、正文、互动数据），这是其他助手没有的。

### 3.5 快捷键（⚠️ 具体键位需确认）
- Enter 发送 / Shift+Enter 换行（高置信）。
- 新建对话 / 搜索会话 / 折叠侧栏 等应用级快捷键存在，但**具体组合键需实机确认** ⚠️。
- X 内：侧栏/标签页呼出 Grok。

### 3.6 附件 / 语音 / 图像
- **附件**：回形针上传图片/PDF，支持拖拽与粘贴。
- **图像生成（Imagine）**：内联产出图片，附下载 / 重新生成 / 变体操作 ⚠️。
- **语音（Voice）**：独立语音模式，通常配**动态波形/光球动画**与多种音色人格 ⚠️。

### 3.7 消息级操作与产物
- 复制、重新生成、继续、点踩、分享、编辑提示词。
- 代码块带**复制**（可能含运行）按钮。
- 长报告/Canvas 类产物支持**右侧分栏编辑**、迭代修改 ⚠️。

### 3.8 记忆与个性化
- 具备**跨会话记忆**能力，且**可在设置中查看/清除/开关** ⚠️。
- 设计含义：必须让"它记得什么"**可见可控**，否则信任成本高。

### 3.9 X/Twitter 内嵌交互（独有）
- 与独立网页不同，X 里的 Grok 是**信息流内联/侧栏抽屉**体验：
  - 在帖子上下文中被唤起（如帖子上的 Grok 入口 / `@grok` 回复）；
  - **就地作答**，回答中可引用该帖子及上下文；
  - 可切换/跳转到**完整 Grok 会话**。
- 设计收益：**把"提问"嵌进用户已有的浏览动作里，降低唤起成本**。

### 3.10 交互状态机（时序抽象）
```
Idle ──输入/发送──▶ Submitting ──▶ Streaming(思考/工具/正文) ──▶ Done
                                        │
                                        └──(Stop)──▶ Stopped ⇢ (可 Regenerate)
Streaming 期间可插入：ToolCall 帧 / Citation 帧 / Reasoning 帧 / Image 帧
Error ──▶ 重试入口
```

## 4. Grok vs ChatGPT / Claude / Gemini 的 UI 差异

| 维度 | **Grok** | ChatGPT | Claude | Gemini |
|---|---|---|---|---|
| **主色调** | **黑白单色**，极简冷峻 | 中性灰 + 绿色点缀 | **暖米/陶土橙**（Claude 品牌色） | 蓝紫渐变（Google 四色） |
| **品牌气质** | 极客/叛逆、带幽默文案 | 中性、通用助手 | 温和、学术/写作 | 明亮、生态整合 |
| **暗色默认** | **是（招牌观感）** | 否（可切换） | 否 | 否 |
| **圆角** | 偏大、pill 感强 | 中到大 | 中到大 | 中到大 |
| **首页** | 居中大留白 + 大输入框 | 居中 + 建议卡 | 居中 + 建议卡 | 居中 + 建议卡 |
| **消息气泡** | 用户右对齐气泡；助手全宽无气泡 | 同左 | 同左 | 同左 |
| **模型/模式选择** | **强调"模式"**（Think/DeepSearch/Imagine） | 模型下拉 + 工具开关 | 模型下拉 + 扩展思考开关 | 模型下拉 + Deep Research |
| **思考过程** | "Thought for Ns"可折叠 | 折叠的思考摘要 | 可折叠 extended thinking | 折叠思考 |
| **工具/检索可视化** | **步骤面板 + 知识图谱** | 检索步骤 + 来源 | 检索 + 引用 | 检索步骤 + 引用 |
| **社交内容内嵌** | **独有：X 帖子卡片化** | 无 | 无 | 无（有 YouTube 等生态但非帖子卡片） |
| **平台集成** | **深度绑定 X/Twitter** | 独立 App/插件 | 独立 App/Artifacts | 深度绑定 Google Workspace |
| **独特记忆点** | 黑白极简 + X 内嵌 + DeepSearch 可视化 | 生态最全、最普及 | Artifacts 分栏 + 暖色审美 | 多模态 + 生态联动 |

> 核心一句话：**ChatGPT/Claude/Gemini 靠"彩色 + 生态"做品牌，Grok 反其道而行，用"去色彩 + 极简 + X 深度集成"做辨识度。**

## 5. 可借鉴的设计要点（Borrowable）

1. **极简单色可做强品牌**：去掉彩色噪音、只靠黑/白/灰层级做信息分级，专注度与高级感都高。适合工具型产品。
2. **模式 chip + 预期管理**：把"快/深/思考/生成图"做成显式 chip，让用户理解**为什么这次慢**（延迟/成本可见化）。
3. **思考过程可折叠（"Thought for Ns"）**：既展示能力，又不干扰主答案阅读——默认收起、按需展开。
4. **工具调用与来源作为一等公民**：内联步骤卡片 + 编号引用 + 来源列表，让"agent 干了什么"透明可查。
5. **上下文内嵌式调用**：把 AI 入口嵌进用户已有场景（Grok 嵌入 X 信息流），显著降低唤起成本——可映射到我们自己在工作流中嵌入入口。
6. **DeepSearch 的可视化**：用步骤 + 图谱呈现"研究过程"，比纯文字更可信、更有记忆点。
7. **记忆可见可控**：提供"记得什么 / 清除记忆"入口，降低信任门槛（与本仓库 `BotMemoryPanel` 思路一致）。
8. **Pill 形 Composer + 左动作簇**：附件/生成/模式集中在输入框周边，交互路径最短。
9. **流式 + 可中断 + 消息级重试**：作为现代 AI 页面的**体验下限**，缺一不可。
10. **跟随宿主主题**：嵌入他方产品时（如 X）复用宿主设计语言（字体/主题），降低割裂感。

## 6. 对本项目 my-agent Web 客户端的映射（leader 补充）

> 对照 `docs/design/web-client.md` 的现状（已做：深/浅色令牌、文档流、代码块头部条、
> 悬停复制、流式+停止+插话、审批弹窗、Bot 广场、限宽与「回到最新」）。

| Grok 的做法 | my-agent 的现状 / 可落地动作 | 成本 |
|---|---|---|
| Dark-first 高对比深色令牌 | 已有浅/深主题令牌，可把**高对比深色**提为一等默认 | 低 |
| Composer 内联模式芯片 | **新增**：把 `model` / `backend`（native / pi / opencode）做成输入框旁的就地切换 chip，替代「藏进设置页」 | 中 |
| 可折叠「思考过程」("Thought for Ns") | 已有 `reasoning_delta` 事件源 → 渲染为**默认折叠**的 Think 块，流式中展开、完成后可收起 | 低 |
| 工具调用一等公民 | 已有 `tool_started` / `tool_finished`，坚持渲染 **ok / error / blocked** 三态卡片 | 已具备 |
| 检索来源列表（DeepSearch） | 若接 web 检索，仿其把来源做成**可点击脚注列表** | 中 |
| 空状态仪式感 | 已有；保持「大标题 + 居中提问框」 | 低 |
| 记忆可见可控 | 已有 `BotMemoryPanel`，方向正确；可补「它记得什么」摘要入口 | 低 |
| 语音 orb | 远期：若做语音，参考**全屏语音球**而非嵌入式播放控件 | 高 |
| 上下文内嵌式调用 | 理念映射：把 agent 入口嵌入用户已有工作流（如本仓库的 DM / Bot 广场） | — |

**一句话结论**：Grok 对本项目最有价值的启发是 **① 深色优先的令牌化主题**、**② Composer 内联 backend/model
芯片**、**③ `reasoning_delta` 折叠思考块**——三者都能在现有事件与组件上低/中成本落地。
