## 1. 问题（读码确认，带证据）

前端有零星断点，但**移动端是「藏起来」而不是「可用」**：

| 现状 | 证据 | 问题 |
|---|---|---|
| `≤640px` 侧栏 `display:none` | `styles.css:3358-3360` | **手机上没有导航入口** → 无法切会话/房间/视图，功能死路 |
| `≤640px` 文件面板 `display:none` | `styles.css:3361-3363` | 手机上看不到/打不开文件面板 |
| `.app { height: 100vh }` | `styles.css:219-223` | 移动浏览器地址栏导致**底部被裁**；未用 `dvh` |
| 无安全区适配 | 全仓无 `safe-area`/`viewport-fit` | 全面屏刘海/手势条遮挡底栏与输入区 |
| 无移动导航组件 | 全仓无 `drawer`/`hamburger`/`overlay`/`mobile` 任何实现 | 缺可达性方案 |
| 弹窗固定宽 + `100vh` 上限 | `styles.css:2203` `.modal{width:440px;max-height:calc(100vh-32px)}` | 移动端高度计算不准、键盘弹出易挤 |
| 触屏悬浮操作 | 仅 `styles.css:1089` 一处 `@media (hover:none)` 兜底 | 其余 hover-only 操作在触屏无等价路径 |

**结论**：现有 `≤640px` 规则是「桌面缩水版」而非移动适配；核心缺口是 **可达性（导航/文件面板）** 与 **视口/安全区**。

---

## 2. 目标与非目标

### 目标
- 手机（竖屏 ~320–640px）上**全部核心功能可达**：切会话/切区域/切视图、发消息、看文件、批复权限。
- 无横向溢出、无底部裁切、无被键盘遮挡的输入框。
- 触控可用：点击目标够大、hover 操作有触屏替代。
- **桌面零回归**（≥881px 视觉与布局不变）。

### 非目标
- 不做 PWA/离线/安装、不做手势库、不做 TUI。
- 不改协议/服务端/`shared/**`/`src/tui/**`/`screenshots/**`。
- 不引入 jsdom/@testing-library（沿用 FR-5/FR-9 硬约束）。

---

## 3. 功能需求（FR）

- **FR-1 视口与滚动**：使用 `100dvh`（回退 `100vh`）；设置 `viewport-fit=cover`；页面**无横向滚动**；`.app` 在移动端不做 WebKit 橡皮筋外的裁切。
- **FR-2 导航可达（核心）**：`≤640px` 不得仅 `display:none` 侧栏；必须提供**可达的导航入口**（暂定：移动端顶栏 + 汉堡 → 抽屉式侧栏，复用现有 `Sidebar`，含「区域 tab / 导航 / Bots / Rooms / 历史会话」）。**关闭抽屉后可回主区**。
- **FR-3 文件面板可达**：`≤640px` 文件面板必须能打开（暂定：全屏/抽屉式覆盖层，可关）。桌面保持右侧栏现状。
- **FR-4 触控可用性**：主要可点元素 ≥ **44×44px** 或等效间距；`hover` 才出现的操作（消息操作条、会话行尾动作等）在 `hover:none` 下有可见/可点路径。
- **FR-5 输入区**：键盘弹出时 `Composer` 保持可见可用（底部 `env(safe-area-inset-bottom)` + 视口单位；避免被浏览器 UI 吃掉）。
- **FR-6 弹窗适配**：`.modal` 移动端宽度 ≤ `100vw - 边距`、高度用 `dvh` 且内容可滚；`PermissionModal` 的许可按钮在窄屏可点。
- **FR-7 桌面零回归**：`≥881px` 的布局/间距/像素不变；`640 < width ≤ 880` 现状规则（窄侧栏 200px）不被破坏。
- **FR-8 范围与可测性**：改动仅 `web/**`；新增**判断逻辑**（如断点/抽屉开合状态机）须为**纯函数**（无 React/DOM）、落 `test/web/*`；纯 CSS 与交互行为按**人工/集成**标注，**不当绿报**。

## 4. 暂定决策（pm 代决，architect 可优化）

> 用户授权自决；以下为默认方案，architect 若发现更优/更简方案可改，但**范围红线与 FR-8 可测性不可改**。

| # | 决策 | 取值 |
|---|---|---|
| M1 | 断点 | 沿用现有 **640px**（移动）/ **880px**（窄桌面），不新增断点 |
| M2 | 导航形态 | **顶栏 + 汉堡 → 抽屉**（复用 `Sidebar`，覆盖式 + 背板点击关闭） |
| M3 | 文件面板形态 | **覆盖层抽屉**（默认关，右侧滑入或全屏） |
| M4 | 区域 tab（分区线） | 移动端保留在抽屉内与/或顶栏，二者择一由 architect 定 |
| M5 | 视图状态 | 抽屉开合为**客户端 UI 状态**，不持久化、不入协议 |
| M6 | 触控目标 | **44px** 下限（Apple HIG） |

## 5. 验收标准（AC）

> 自动绿 = 纯函数用例（`test/web/*`，无 jsdom）；其余为**人工/集成**，须显式标注、不计自动绿。

- **AC-1 断点/状态纯函数（自动绿，若引入）**：任何新增判断逻辑（断点常量、`isCompact(width)`、抽屉开合机）有纯函数单测；无 jsdom。（若最终为纯 CSS、无新逻辑，则本 AC 标注 N/A 并在测试计划说明。）
- **AC-2 无横向溢出（人工/集成）**：在 **320 / 375 / 414 / 768 / 1024 / 1440** 宽度下无横向滚动条、无内容被裁；`dvh` 生效、底部不被浏览器 UI 裁切。
- **AC-3 移动导航可达（人工/集成）**：`≤640px` 能打开抽屉并完成：切区域（助手/Bot）、切视图（对话/广场/子 Agent/Agents）、切会话、切房间；关闭后回主区。
- **AC-4 文件面板可达（人工/集成）**：`≤640px` 能打开文件面板并浏览/返回，不遮挡到无法操作。
- **AC-5 触控目标（人工 + CSS 审查）**：主要可点元素 ≥44px 或等效间距；`hover:none` 下 hover-only 操作有替代。
- **AC-6 弹窗适配（人工/集成）**：`.modal`/`PermissionModal` 在 320–375px 宽度下完整可见、可滚动、按钮可点。
- **AC-7 桌面零回归（人工）**：`≥881px`（含 1024/1440）布局与现状一致；`640–880` 现状规则不破。
- **AC-8 范围红线（自动/审查）**：diff 仅 `web/**`（+ 如必需 `web/index.html`）；**零命中** `shared/protocol.ts`、`src/rob/room-text.ts`、`src/tui/**`、`screenshots/**`；未引入 jsdom/@testing-library。

## 6. 风险与依赖

- **可达性改动会动 `App.tsx`/`Sidebar.tsx`** ⇒ 与分区线（`a063851`）同文件；必须基于 `a063851` 起分支，避免落后基线。
- **移动导航与区域 tab 叠加** ⇒ 信息架构需与设计 §1 对齐（助手/Bot 分区在移动端仍成立）。
- **`100vh`→`100dvh`** 属全局改动，需确认桌面不回退。
- **无 jsdom** ⇒ AC-2..AC-7 只能人工/集成，测试计划须显式标注，**不得当绿报**。
- **回归保护**：分区线 AC-1..AC-8、@ 选择器线 AC-1..AC-13 不得回归（`test/web/*` + `test/rob/room-text*` 全绿）。
