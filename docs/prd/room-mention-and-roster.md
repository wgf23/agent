# PRD：房间 @ 成员选择器 + 成员名册

- 状态：confirmed（范围已由用户拍板，见 §6）
- 作者：pm
- 关联：`src/rob/room-text.ts`（`parseRoomMentions`，`@name` / `@all` 已有后端语义）、`web/src/components/RoomView.tsx`（房间输入框）、`web/src/state.ts`（`ClientRoom.members`、`botStates`）、`web/src/status.ts`（`STATUS_LABEL`）

## 1. 背景与问题

房间（群组）已支持用 `@名字` 指定发言人：

- 后端 `parseRoomMentions` 只把**精确匹配的成员名**当作 mention，未匹配的 token 原样留在正文；`@all` 广播给所有成员。
- 客户端**没有任何提示**：`RoomView` 输入框只有一句 placeholder「@成员 可指定回应者…」，用户必须**手打完整成员名**，拼错就静默无效。
- 群里都有谁，目前只显示一个数字（输入框页脚 `{room.members.length} 名成员`），看不到具体成员名单，也看不到成员状态。

结论：功能已存在但「发现性」与「可用性」缺失，本次补齐——@ 选择器（autocomplete）与成员名册（roster，点击打开的浮窗）。

## 2. 目标与非目标

### 目标
1. 键入 `@` 时弹出**当前房间成员**候选项，键盘/鼠标选择后插入，避免手打与拼错。
2. 提供**点击打开的浮窗**查看房间成员名单（谁在群里、谁是协调者、各自状态）。

### 非目标（本次不做）
- 不改后端 mention 解析规则（`parseRoomMentions` 语义不变：精确匹配 + `@all`）。
- **不做 TUI**（二期再做）；本次只做 Web UI。
- 不做成员增删/邀请 UI（成员仍由 `rooms` 配置与既有成员事件管理）。
- 不做 Bot 单聊（DM）的 @ 选择器（DM 无成员概念）。
- 不做常驻成员侧栏（用户明确要**点击打开的浮窗**）。
- 不做 @all 的权限/限流策略（沿用现有行为）。

## 3. 用户故事

- US-1：敲 `@` 看到成员候选，方向键选中、Enter/Tab 插入，不用记名字。
- US-2：打 `@de` 候选按前缀过滤到 `dev`；无匹配时明确反馈。
- US-3：候选里有 `@all`（已 @ 过的成员被排除）。
- US-4：点一下就能看到群成员名单，含**每个成员的状态**与协调者标记。
- US-5：成员变化后，候选与名册同步更新。

## 4. 需求明细

### FR-1 @ 触发与候选来源
- FR-1.1 在房间输入框光标处输入 `@` 时弹出候选浮层。
- FR-1.2 候选 = 当前 `ClientRoom.members`（保持服务端成员顺序）∪ `{all}`，**再按 FR-2.7 排除已 @ 的成员**。存在名为 `all` 的成员时按精确名优先（与后端一致，此时 `all` 即该成员，不做广播语义）。
- FR-1.3 `@all` 项需有区分文案（如「所有人」）。
- FR-1.4 **Token 规则（与后端 `parseRoomMentions` 完全一致，必须同源同语义）**：mention token = `@` + **贪婪**匹配 `[a-z][a-z0-9-]*`。要点：
  - `-`（连字符）**属于**名字字符集，不是终止符：`@dev-` 的 token 是 `dev-`（若存在成员 `dev-` 则命中它，否则不命中任何成员）。**不得**把 `@dev-` 截成 `dev`。
  - 字符集外的字符终止 token：`,`、`@`、空格、中文、大写字母（大写不在 `[a-z]` 内）等。
  - 大小写敏感（后端如此）：`@deV` 的 token 是 `de`，残留 `V`。
  - 边界示例：`@dev,`→`dev`；`@dev@x`→`dev`（残留 `@x`）；`@dev@`→`dev`（残留 `@`）；`@deV`→`de`（残留 `V`）；`@dev `→`dev`。
  - **适用范围**：本严格规则约束**后端语义与"已 @ 排除"的判定**——即发送后 `addressed` 的取值、FR-2.7 的已 @ 排除、AC-11/AC-12 真值表。UI 在**光标处解析"正在输入的查询"**时另用较宽规则（见 FR-2.1），但插入结果一律回填规范小写名，不产生前后端分叉。

### FR-2 过滤与插入
- FR-2.1 **查询过滤（UI 便利，大小写不敏感）**：光标处的查询以 `@` 起、后接**大小写不敏感**的 `[A-Za-z][A-Za-z0-9-]*`（仅用于 UI 查询匹配与替换区间计算），按**小写**做前缀过滤；**插入一律回填规范成员名** `@<规范小写名> `（如候选 `dev`，输入 `@DEV` 选中后插入 `@dev `）。因后端大小写敏感，「手打全大写且不经候选插入」不生效——记为**已知行为**，不作为缺陷。
  - **与 FR-1.4 的分工（不得混用）**：FR-1.4 的严格 `[a-z]` 规则用于**后端语义判定**（发送后 `addressed`、FR-2.7 排除、AC-11/AC-12）；FR-2.1 的宽规则**只用于光标处的查询解析与替换区间**。替换区间只能覆盖「`@` + 已输入查询」，不得吞掉无关文本。
  - **`@DEV` 场景（必须正确）**：查询 `DEV` → 忽略大小写命中 `dev` → 替换 `@DEV`（anchor 指向 `@`、length=4）→ 插入 `@dev `。**不得**出现只替换 `@`（length=1）而残留 `DEV` 的行为。
  - 边界：查询首字符为字符集外字符（如 `@1`、`@ `、`@×`）时视为无有效查询，关闭候选浮层（不展示"全部成员"）。
- FR-2.2 键盘：`↑/↓` 移动高亮（循环），`Enter` 或 `Tab` 选中并插入，`Esc` 关闭浮层且**不发送**消息。
- FR-2.3 鼠标：点击候选项插入；点击浮层外关闭。
- FR-2.4 插入结果为 `@<name> `（含尾随空格），插入点在**当前光标处**，**替换区间 = `@` 起点到 Q-token 末尾**（不是仅到 caret）；不破坏前后文本。
  - **caret 落在 token 内部时也必须延伸到 token 末尾**：如 `"@de|v"`（caret 在 token 中间）选中 `dev`，结果须为 `@dev `，**不得**残留 `ev`（不得产生 `@dev ev`）。
  - caret 在 token 末尾（常态）时 token 末尾 = caret，行为与「替换 `@` + 查询前缀」一致。
  - 替换区间的起点（anchor）与终点由 FR-5 的纯函数按 **FR-2.1 的 Q 规则**给出，终点不得越出该 Q-token 范围、不得吞掉 token 之后的无关文本。
- FR-2.5 不改变既有发送语义：`Enter`（无浮层激活）仍发送，`Shift+Enter` 换行，中文 IME 组合中（`isComposing`）不触发选择/发送。
- FR-2.6 允许连续 @ 多个成员（插入后再次输入 `@` 仍可再选）。
- **FR-2.7 排除已 @**：候选隐藏**当前输入框文本中作为 mention 出现的名字**——判定必须使用 **FR-1.4 的同一 token 规则**（`@` + 贪婪 `[a-z][a-z0-9-]*`，精确等于成员名，或精确等于 `all`）。
  - 因此 `@dev-` **不**隐藏 `dev`（其 token 为 `dev-`，不等于 `dev`）；`@dev ` 才隐藏 `dev`。
  - `@all` 只隐藏 `all` 项，不隐藏全部成员候选。
  - 被排除的成员仍可**手打**，不影响发送；排除仅作用于候选展示。

### FR-3 成员名册（点击打开的浮窗）
- FR-3.1 房间页提供**一处**入口（建议页脚「N 名成员」可点），点击打开浮窗展示完整成员名单，保持成员顺序。
- FR-3.2 名册标出**协调者**（`room.coordinator`）。
- FR-3.3 **显示每个成员的状态**：复用 `state.botStates[member]?.status` + `STATUS_LABEL`（空闲/工作中/等待审批/已停止）；无状态数据时按 `idle` 呈现。
- FR-3.4 名册是**全量**名单（不受 FR-2.7 排除影响），点 `Esc`/点外部/再点入口可关闭。
- FR-3.5 名册与 `@` 候选同源（均来自 `ClientRoom.members`），成员变化后同步更新，不得只更新一处。
- FR-3.6 成员为空时名册显示空态文案。

### FR-4 数据来源（不新增协议）
- FR-4.1 复用已有 `ClientRoom.members`、`room.coordinator`、`state.botStates`（状态）；不新增服务端事件/字段。若实现中确需，回抛 pm/architect 走变更。
- FR-4.2 `RoomView` 需新增 `botStates` prop（`App.tsx` 已有 `state.botStates` 可传）。

### FR-5 可测性（纯逻辑抽离）—— 硬约束
- FR-5.1 本仓 web 层**没有 jsdom / @testing-library**，`test/web/*` 全是纯逻辑用例。因此 @ 选择器的**查询解析、候选集合计算、替换区间（anchor/length）**必须抽成**独立纯函数模块**（如 `web/src/mention.ts`），组件（`RoomView`）只负责事件绑定与渲染。
- FR-5.2 纯函数须覆盖：`@` 触发判定、前缀过滤、已 @ 排除（FR-2.7）、插入替换区间（FR-2.4/AC-3）、边界字符截断（FR-1.4/AC-12）。AC-1/2/3/6/7/12 的**逻辑断言落在 `test/web/` 的纯函数用例**上；UI 交互仅在无法纯测处做人工/集成验证。
- FR-5.3 不得为通过测试而引入新测试依赖（jsdom 等）——保持与现有 web 测试栈一致。

## 5. 验收标准（AC）

> 交 qa 补测试、review 按此审。web 层用例与后端 `parseRoomMentions` 既有用例分层，不混淆。

- AC-1 输入 `@` 出现候选浮层；候选集合 = 房间成员 ∪ {`all`}，顺序与 `members` 一致。
- AC-2 `@d`（成员含 `dev`）过滤为 `dev`；`@zz` 不展示成员候选。
- AC-3 `↑/↓` 切换高亮；`Enter`/`Tab` 选中后文本为 `@<name> `，且**插入发生在光标处**（在文本中间插入不破坏前后内容）。**caret 落在 token 内部时替换延伸到 token 末尾**：`"@de|v"` 选中 `dev` → `@dev `（无残留 `ev`）。
- AC-4 浮层开启时 `Esc` 关闭**且不发送**；此时按 `Enter` 是选择候选而非发送。**回归保护**：浮层关闭且房间 running 时，`Esc` 仍须触发既有「中断本次发送」行为（不得因新增浮层而吞掉）。
- AC-5 选中 `@all` 后发送，后端 `parseRoomMentions` 判定 `addressed` = 全部成员（**复用既有后端用例**，不重写）。
- AC-6 中文 IME 组合（`isComposing`）期间候选与 Enter **均不误触发**，且此守卫为**必需**（非可选），分两条取证：
  - `Enter` 抑制：`mentionKeydown({isComposing:true,...}) → "none"`（纯函数，可自动测）；
  - 合成期**不产生候选浮层**：组件级行为（`onChange` 合成中间态不得弹出候选），标注为人工/集成验证；若 architect 选择给 `mentionState` 增加 `isComposing` 入参以实现纯测，需同步更新签名与 `test/web/` 用例。
- AC-7 连续 @ 不同成员（如 `@a @b`）两次插入均正常；**重复 @ 同一成员（token 精确等于该成员名，如 `@dev `）时该成员从候选中消失（FR-2.7）**，但仍可手打。注意：`@dev-` 的 token 是 `dev-`，**不**使 `dev` 从候选消失（与 FR-1.4 token 规则一致）。
- AC-8 点击名册入口打开浮窗，列出**全部**成员且顺序正确，标注协调者，且**显示各成员状态**（命中 `STATUS_LABEL`）。
- AC-9 成员变化（`members` 事件）后，候选与名册**同时**更新；建议在 state 层断言同源（均基于 `ClientRoom.members`），UI 层再各测一次。
- AC-10 房间无成员时名册显示空态文案，不报错、不空白。
- AC-11 手打未匹配的 `@xxx` 行为不变：仍在正文保留且不产生 addressed（回归保护，不引入新语义）；`test/rob/room-text.test.ts` 保持绿。
- AC-12 边界 token 与后端 `parseRoomMentions` **完全一致**（`@` + 贪婪 `[a-z][a-z0-9-]*`）：`@dev,`→`dev`；`@dev@x`→`dev` 且残留 `@x`；`@dev@`→`dev` 且残留 `@`；`@deV`→`de` 且残留 `V`；`@dev `→`dev`；**`@dev-`→ token 为 `dev-`（`-` 是名字字符，非终止符），存在成员 `dev-` 时命中它、否则不命中**。前端不得与后端分叉（不允许「前端截 `-`」）。AC-12 逻辑断言以 `test/web/` 纯函数用例取证，并与后端 `test/rob/room-text*.test.ts` 语义互证。
- AC-13 大写查询：在 members 含 `dev` 时输入 `@DEV`，候选按忽略大小写过滤命中 `dev`；选中插入结果为 `@dev `，替换区间覆盖 `@DEV`（length=4），**文本中不残留 `DEV`**。若用户不经候选、直接发送手打 `@DEV`，行为以后端为准（不 addressed，已知行为）。

> 可测性约束（FR-5）：本仓 web 层无 jsdom/@testing-library。AC-1/2/3/6/7/12 的逻辑断言应以 **`web/src/mention.ts` 纯函数 + `test/web/*` 单测**取证；组件只做事件绑定，UI 行为靠人工/集成补充。不得新增 jsdom 等测试依赖。
